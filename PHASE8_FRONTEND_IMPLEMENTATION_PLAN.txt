workspaces, documents, retrieval, generation, chat, review, export) and is

5. ARCHITECTURE DECISION RECORD
--------------------------------------------------------------------------------
* Auth: Supabase Auth (single provider, per backend deps.py + SUPABASE_INTEGRATION.md).
  Backend M1 password scaffold (backend/auth + demo users) is TEMPORARY and
  must NOT be built upon. Decision: FastAPI validates the Supabase JWT the
  frontend already attaches (http.ts:45). Implementation options: (a) decode+
  verify JWT with PyJWT using Supabase JWT secret, (b) call Supabase
  Auth admin REST /userinfo per request (slower), or (c) supabase-py with
  service-role to look up user. Recommended: (a) stateless JWT verify, fallback
  (b) for revocation.
* DB: Supabase Postgres for users/profiles/workspaces/documents (already used
  by auth.api/workspace.api/document.api). Backend SQLite (ingestion.db)
  stays the platform/operational DB per Phase 8 backend. DATABASE_SCHEMA.md is
  the Supabase schema reference.
* Storage: Supabase Storage bucket "documents" for raw files (document.api.ts
  writes via supabase.storage); backend tracks storage_path per upload contract.
* Content search/RAG: Chroma (backend CHROMA_DIR) — frontend only calls
  GET /search + /documents/{id}/chunks.
* API transport: src/api/http.ts is the single network path (AGENTS.md rule 5).

7. CRITICAL BLOCKERS (P0)
--------------------------------------------------------------------------------
B-01  Backend must accept the Supabase JWT the frontend already sends.
      Evidence: src/api/http.ts:45 attaches "Authorization: Bearer <token>";
      frontend auth.api.ts:90-119 signs in via supabase.auth and hands the
      access_token to http.ts via setAccessToken. Backend deps.py still uses
      the M1 password scaffold (get_current_user reads the scaffold token), so
      every real HTTP call to /generate/*, /search, /chats, /review, /history
      will be rejected (401) or mis-authenticated.
      Files: backend/deps.py, backend/auth/router.py; frontend src/lib/supabase.ts,
      src/api/auth.api.ts, src/api/http.ts.
      Required fix (backend): implement verify_supabase_jwt() and rewrite
      get_current_user()/require_role() to decode+verify the Supabase access
      token (aud "authenticated", iss = SUPABASE_URL/auth/v1), mapping the
      sub -> platform user; delete/shelve the M1 password auth after the flip.
      Priority: P0.

B-02  Review backend crash: ReviewAction enum mismatch.
      Evidence: backend/src/validation/review_schema.py defines ReviewAction =
      APPROVE | EDIT | REJECT | COMMENT (no NEEDS_EDIT, no FLAG); backend/review/
      service.py ~lines 64-70 references ReviewAction.NEEDS_EDIT and
      ReviewAction.FLAG -> AttributeError on real review calls. Frontend
      paths.ts:61-70 already calls /review/needs-edit and /review/flag.
      Files: backend/src/validation/review_schema.py, backend/review/service.py.
      Required fix (backend): extend ReviewAction with NEEDS_EDIT and FLAG (or
      align the action_map to the enum). Priority: P0 (blocks M7 in real mode).

B-03  No .env.example in the frontend repo.
      Evidence: repo has only .env.local (git-ignored). A fresh clone has no
      VITE_ENABLE_MOCK=false and no VITE_API_BASE_URL, so isMockMode() returns
      true (env.ts:28/35) and the app silently runs on mock data.
      Required fix (frontend): commit .env.example with all VITE_* keys
      documented; gitignore currently allows it (!.env.example) so it just
      needs creating. Priority: P0 (onboarding correctness).

12. ERROR HANDLING (frontend)
--------------------------------------------------------------------------------
Current (http.ts): single HttpError(status, message, body); no 401 auto-refresh;
no status-specific shaping; timeouts abort at 90s and throw a generic message.
Required:
  * 401 -> refresh Supabase session once, retry request; on refresh failure,
    sign out + route to login (F-8).
  * 403 -> user message "you do not have permission" + RoleGate behavior.
  * 404 -> workspace/document-not-found copy (no blank page).
  * 409 -> duplicate/resource conflict copy (workspace create, upload dup).
  * 413 -> "file too large — max <backend limit> MB" using backend message
    (F-6, BF-8).
  * 422 -> show validation detail (field-level) from error envelope
    {error:{code,message,details}}.
  * 429 -> retry-after / cool-down message (LLM rate limits).
  * Timeout/abort -> surface "request timed out" (already partially done,
    http.ts:68).
  * Add a shared error-shaping module (single path, AGENTS.md rule 5) mapping
    status -> user-facing copy, and ensure errors surface through the existing
    toast()/ErrorState patterns (components/app/AsyncState.tsx).
