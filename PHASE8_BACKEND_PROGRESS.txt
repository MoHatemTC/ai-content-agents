(3) Metadata persistence — CONFIRMED, columns live in the documents table
    (backend/documents/migrations.py), not adapter-only:
      * notes      -> documents.notes                (PATCH /notes round-trip)
      * tags       -> documents.tags_json (JSON)     (default [])
      * status     -> documents.status (DB enum uploaded|parsing|embedding|
                     indexed|failed) -> API Ready|Processing mapping
      * pages      -> documents.pages + page_offsets_json (PDF only)
      * size       -> documents.size_bytes + size_human
      * storage_path -> documents.storage_path (+ file_bytes BLOB)
    All persisted through embed; read back in GET /documents and
    GET /documents/{id}.

(4) Empty Chroma collection on delete — EVALUATED. DELETE /documents/{id}
    removes the document's index rows via ChunkIndex.remove_document but
    leaves the (possibly empty) per-workspace collection object on disk.
    DECISION: defer auto-collection-deletion. Chroma has no delete-by-name
    on a PersistentClient without re-instantiation, and an empty collection
    is inert (costs ~0, search returns []). Revisit at M11 / Supabase flip;
    the chroma dir is documented as disposable (re-ingest to rebuild).
