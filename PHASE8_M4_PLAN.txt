2. ENDPOINT SATISFIED
   GET /search?q=&workspace_id=&limit=&kinds[]=   -> 200 {results, total}
     - Contract: SearchQuery {q, workspaceId?, kinds?, limit?} /
       SearchResponse {results: SearchResult[], total}
       (Sensei-AI/src/types/api/catalogue.contracts.ts:46-55).
     - SearchResult {id, kind:"document", title, subtitle?, to}
       (src/types/domain.ts:203-210). Mock shape for document results:
       title = document title, subtitle = "{kind} · {pages} pages",
       to = "/library", id = document id.
     - search.api.ts only appends workspace_id, limit and kinds; q is
       required by the client. Backend treats missing workspace_id as 422
       (consistent with GET /documents), unknown -> 404, cross-owner -> 403,
       no token -> 401. limit defaults to 40 (mock default).
   Not in M4: /documents/{id}/chunks already ships in M3; no other search
   endpoint exists in paths.ts.

5. DESIGN DECISION REQUIRING YOUR APPROVAL — WORKSPACE-WIDE SCOPE
   /search targets a whole workspace, but RetrievalScope structurally
   requires document_id and/or session_id ("unscoped retrieval is not
   allowed"). Since each workspace IS one Chroma collection, workspace-wide
   retrieval must query the collection with NO metadata filter.
   Options:
   A) EXTEND src/retrieval/models.py RetrievalScope with an optional
      workspace_id field; when set alone, to_where() returns no Chroma
      filter (None). ~15 lines in the ONE src file, principled, and it
      serves M6 workspace chat too. [RECOMMENDED]
   B) Backend adapter bypasses the scope and queries Chroma with where=None
      directly — duplicates ChromaRetriever's min_score/ranking/clamp logic.
      Rejected.
   C) Enumerate document_ids() and issue per-document queries — N round-trips,
      and RetrievalScope has no $in support. Rejected.
   M3 left src/ untouched; this is the first deliberate domain extension.
   Please confirm A (or propose otherwise) before I code M4.

6. STATUS CODES / ERROR ENVELOPE
   Reuse backend/errors.py ApiError envelope {error:{code,message,details}}:
   401 unauthorized (no/invalid token), 403 forbidden (non-owner workspace),
   404 not_found (unknown workspace), 422 validation_error (missing q /
   missing workspace_id), 200 on success. 429/413 handled elsewhere (rate
   limit middleware, upload guard) — unchanged.

7. SEARCH SEMANTICS (documented, not aspirational)
   - Ranking is exact/keyword via the embedder in use: hashing (default for
     tests/offline) is deterministic bag-of-words; onnx is semantic. M4
     surfaces whatever ChromaRetriever returns, min_score-filtered, so
     results are honest about the current embedder (analysis 4.4).
   - Blank/whitespace q -> {results: [], total: 0} (ChromaRetriever short-
     circuits blank queries).
   - subtitle uses the same "{kind} · {pages} pages" shape as the mock;
     pages is null for non-PDF so the subtitle shows the kind only.
