Architecture discovered:
  - Strict layering: routes/ -> components/ -> contexts/&hooks/ -> services/
    -> api/ -> mock/ -> types/. UI never imports src/api or src/mock.
  - src/api/http.ts is the SINGLE network path: every *.api.ts module
    short-circuits to src/mock when isMockMode() and otherwise calls http.*
    against env.API_BASE_URL. AuthService feeds the one access token via
    setAccessToken().
  - Response rule: http.ts auto-unwraps { data: T } when present, otherwise
    returns the payload verbatim. Errors are thrown as HttpError(status, msg,
    body) and mapped to Result<T> by src/lib/result.ts attempt().
  - The api modules ALREADY route generation/chat/review/history/analytics/
    models/search/catalogue through http.*. ONLY workspace.api.ts and
    document.api.ts (list/create/update/delete/upload) still read/write
    Supabase directly in non-mock mode.
  - Auth (auth.api.ts) intentionally stays on the Supabase JS client
    (identity + session persistence + refresh), and its access token is
    forwarded to http.ts for every API request.
  - Endpoint contract gap found: /agents, /pipeline/*, /catalogue,
    /notifications*, /search are called by catalogue.api.ts + search.api.ts
    but are NOT yet listed in docs/FASTAPI_INTEGRATION.md. Registered in the
    new endpoint registry with a "consumer-defined" note.

Changes completed:
  1. Created src/api/paths.ts — a single, central registry of every endpoint
     the frontend calls, grouped by domain, with parameterized-path helpers
     (e.g. paths.documents.parse(id)). Derived strictly from
     docs/FASTAPI_INTEGRATION.md + docs/BACKEND_CONTRACT.md and, for the
     endpoints the api modules already call but the docs do not yet list
     (/agents, /pipeline/*, /notifications*, /catalogue, /search), recorded
     with an explicit "consumer-defined" note so the backend team has the full
     inventory. No invented endpoints.
  2. Wired every http-based api module to paths.ts (inline path literals
     removed): generation.api.ts (5 paths), chat.api.ts (4), review.api.ts (7),
     history.api.ts (1), analytics.api.ts (1), model.api.ts (1),
     search.api.ts (1), catalogue.api.ts (8), document.api.ts http branches (5).
  3. Hardened src/api/http.ts for backend traffic:
     - BASE_URL = env.API_BASE_URL with trailing slashes stripped, so
       "http://localhost:8000/api/v1/" and "http://localhost:8000/api/v1"
       both work and never produce double slashes.
     - DEFAULT_TIMEOUT_MS = 90s via AbortController, active only when the
       caller does not supply its own signal. An abort surfaces as
       "Request timed out after 90s." instead of a bare browser AbortError.
     - Existing behaviours preserved: Bearer header from the single
       access-token holder, { data } auto-unwrap, HttpError shaping, FormData
       passthrough, 204 → null.

Why each change was made:
  - paths.ts gives the backend a single auditable file listing every route the
    frontend requests, eliminating string-literal drift across nine api
    modules. Adding/renaming an endpoint is now a one-file change plus its
    consumer (BACKEND_CONTRACT.md rule 4). Mock-mode behaviour is untouched, so
    nothing observable changes while VITE_ENABLE_MOCK stays on.
  - Wrapping the base URL once (instead of string-interpolating on every call)
    means the switch to the live FastAPI base never has to remember to strip a
    trailing slash, and the default "/api" mock base keeps working unchanged.
  - The timeout guards against a stalled backend hanging the UI; it is opt-out
    only for callers that already manage an AbortSignal (e.g. an in-flight
    chat generation cancelled by the user).
