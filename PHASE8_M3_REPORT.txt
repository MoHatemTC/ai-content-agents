4. ARCHITECTURE DECISIONS
   a) FastAPI layer owns the workspace-scoped read model. The `src/` ingestion
      store (SQLiteStore) is single-user, has no workspace/notes/status/
      storage_path columns, and its Library.delete vs Store.delete are separate
      code paths. Rather than force multi-workspace semantics onto it (or risk
      the delete divergence the analysis warns about), backend/documents owns
      the records; the pure domain *algorithms* are reused (section 5).
   b) Stored file bytes in the documents table (BLOB), not a filesystem dir.
      Self-contained (single DB file), no uploads/ path config, and consistent
      with the Supabase Storage model the frontend will keep in production —
      the API's storage_path is the virtual "{workspace}/{doc}/{filename}" path
      the contract specifies.
   c) Status lifecycle: DB rows carry the DATABASE_SCHEMA.md enum
      (uploaded|parsing|embedding|indexed|failed); the API WsDoc.status exposes
      the frontend's Ready|Processing pair — uploaded/indexed -> Ready,
      parsing/embedding/failed -> Processing. Upload starts "Ready", parse and
      chunk move it to parsing, embed to embedding then indexed.
   d) One Chroma collection per workspace (`workspace_<id>`), so embed/delete
      never leak across workspaces. persist_directory = Settings.chroma_dir
      (empty string in tests -> ephemeral in-memory index; set in prod -> disk).
   e) Quality gate at parse, mirroring the src/ Loader: content failing
      QualityChecker yields 422 validation_error with the issues in details and
      the row marked failed — rejected, not stored for chunking.
   f) Pipeline order enforced: chunk before parse -> 409 conflict; embed before
      chunk -> 409 conflict (matches the frontend's sequential drive).
   g) M1 custom auth is marked TEMPORARY SCAFFOLD everywhere (docstrings +
      deps.py note): Supabase is the single auth provider; the password/session
      scaffold is replaced by Supabase JWT verification in that milestone. M3
      reuses get_current_user unchanged and adds no auth decisions on the
      scaffold's role model (ownership checks only).

15. DEVIATIONS & TRADE-OFFS
    - WsChunk.page: None for non-PDF (TXT/DOCX/MD have no page concept) and a
      real 1-based page for PDFs; the TS type declares number but the frontend
      does not consume chunks in non-mock mode today.
    - WsChunk.section/tags always empty for now (the chunker produces no
      section/topic metadata); columns exist so they can be filled later
      without a migration.
    - The pipeline runs synchronously per request; a large PDF embeds in the
      same request (acceptable for M3, see risks).
    - Embed uses the RETRIEVAL_EMBEDDER label (hashing/onnx) as the response
      model name — truthful to the embedder actually used.
    - File bytes live in SQLite (simple, self-contained) rather than object
      storage; fine until M11's Supabase flip.
