### BUG-002 (Fixed): Flashcard count metric always passes

- Symptom:
  - `count_matches_request` in study evaluation can report success even when fewer cards than requested are generated.
- Root cause:
  - Comparison used `len(cs.cards) >= min(expected_count, max(1, len(cs.cards)))`, which is true when `len(cs.cards) < expected_count`.
- Fix:
  - Enforce exact match: `len(cs.cards) == expected_count`
  - Code: [evaluation.py](file:///d:/Sprint/Sprint_Task1/ai-content-agents/src/study/evaluation.py)
- Verification:
  - Added unit test: `test_flashcard_count_mismatch_is_detected`
  - Code: [test_study_eval.py](file:///d:/Sprint/Sprint_Task1/ai-content-agents/tests/features/test_study_eval.py)

### BUG-003 (Fixed): Plan completeness metric always passes

- Symptom:
  - `all_extracted_topics_scheduled` increments even if the plan schedules only a subset of extracted topics.
- Root cause:
  - Condition `scheduled >= (allowed & scheduled)` is always true because `(allowed & scheduled)` is a subset of `scheduled`.
- Fix:
  - Enforce completeness: `allowed.issubset(scheduled)`
  - Code: [evaluation.py](file:///d:/Sprint/Sprint_Task1/ai-content-agents/src/study/evaluation.py)
- Verification:
  - Added unit test: `test_plan_completeness_requires_all_extracted_topics`
  - Code: [test_study_eval.py](file:///d:/Sprint/Sprint_Task1/ai-content-agents/tests/features/test_study_eval.py)
